# Switcher — устройство, логика и правила

Этот файл — полное описание проекта для человека или ассистента, который будет его править.
Он описывает **что** делает программа, **почему** каждое решение принято именно так, все пороги и константы,
а также грабли, на которые уже наступали. Если меняешь поведение — обнови этот файл.

Актуально для версии **0.1.1** (2026-09-18). Репозиторий: https://github.com/Alex100687/Switcher

---

## 1. Что это

Трей-утилита для Windows (C#, .NET 8, WinForms), аналог Punto Switcher с исправлением опечаток:

1. Следит за набираемым словом через низкоуровневый хук клавиатуры (`WH_KEYBOARD_LL`).
2. На границе слова (пробел / Enter / Tab) решает: слово набрано не в той раскладке, с ошибкой, и то и другое,
   или всё нормально.
3. Стирает слово и перепечатывает правильно (`SendInput`), при необходимости переключая раскладку окна.
4. `Pause/Break` — ручное переключение последнего слова и откат автозамены с самообучением.

Языки: русский и английский (раскладки 0x0419 и 0x0409). Других не поддерживает — `Corrector.Decide` возвращает
`Keep`, если один из языков не поддержан.

Автор и единственный пользователь на момент написания — Алексей Бакакин (Alex100687). Требование пользователя:
**максимально агрессивное исправление**, ложные срабатывания лечить белыми списками и откатом через Pause.

## 3. Поток обработки клавиши (Engine.OnKeyDown)

Хук стоит на UI-потоке (тот же, что трей). Порядок проверок:

1. Инжектированное событие (наша сигнатура или `LLKHF_INJECTED`) → игнор. В тестах `SWITCHER_ACCEPT_INJECTED=1`
   принимает чужой синтетический ввод как аппаратный (свой — всё равно игнорируется).
2. Запомнить время аппаратной клавиши; если есть отложенное исправление и это аппаратная клавиша — **применить его
   сейчас** (см. §7).
3. Горячая клавиша (по умолчанию `Pause`, парсится из `settings.json`, формат `Ctrl+Shift+Key`) при включённой
   программе → обработать синхронно и проглотить. При выключенной — пропустить в приложение.
4. Программа выключена или словари не загружены → пропустить.
5. Голый модификатор (Shift/Ctrl/Alt/Win/CapsLock) → пропустить, буфер не трогать (иначе Alt+Shift сбрасывал бы слово).
   `Win+Space` → пропустить (это переключение раскладки). Любая другая клавиша с зажатым Ctrl/Alt/Win → шорткат:
   `Invalidate()` (сброс буфера + эпоха), пропустить.
6. Определить окно (`GetForegroundWindow`) и раскладку его потока. Фоново обновить детектор паролей.
7. Окно сменилось → `Invalidate()`. Раскладка сменилась при непустом буфере → **ручное переключение посреди слова**
   (§6.3).
8. Клавиша слова (буквы, цифры, OEM-клавиши — в RU это буквы) → `Push`. Цифра ставит флаг `HasDigits` (такие слова
   не трогаем). Буфер > 64 клавиш → сброс.
9. Backspace → снять последнюю клавишу; Backspace при пустом буфере → `Invalidate()` (удаляют предыдущее слово, мы
   больше не знаем, что на экране).
10. Пробел / Enter / Tab при непустом буфере → граница слова (§4). Shift+Enter → просто сброс.
11. Всё остальное (стрелки, Esc, Delete, F-клавиши…) → `Invalidate()`.

Мышь (LL-хук мыши): любой клик → `Invalidate()` + обновить детектор паролей.

**Эпоха** (`_epoch`) — счётчик, растёт на каждой границе слова и каждом `Invalidate`. Отложенное исправление
сравнивает эпоху: если изменилась — на экране уже не то, что мы думаем, исправление пропускается.

## 4. Граница слова (Engine.OnWordBoundary → Corrector.Decide)

Входы: `typed` = рендер буфера в раскладке, в которой набирали; `alt` = рендер в другой раскладке
(`Layouts.Other`: RU↔EN, иначе единственная другая); `hasDigits`; `ctx` — язык контекста окна.
`core`/`altCore` — то же без ведущей/замыкающей пунктуации (`StripPunctuation`: обрезает всё, что не буква/цифра, с
краёв; знаки внутри остаются, поэтому `ghbdtn?` → `привет,` целиком).

Исключённые процессы (`ExcludedProcesses`, по имени процесса окна) → ничего не делаем. По умолчанию: IDE (Code,
devenv, rider64, idea64, sublime_text, notepad++), терминалы (WindowsTerminal, cmd, powershell, pwsh, conhost, mintty,
alacritty, wezterm-gui), Unity, UnityHub, blender, mstsc, vmware, VirtualBoxVM. В тестах `SWITCHER_NO_EXCLUDE=1`.

Порядок правил `Decide`:

1. Словари не загружены, есть цифры, язык не поддержан → `Keep`.
2. `core` пуст → `Keep`. `core` в исключениях/белом списке → `Keep`.
3. camelCase/PascalCase (заглавная не в первой позиции, но не сплошной КАПС) у `core` или `altCore` → `Keep`
   (идентификаторы: `myVar`, `GameObject`).
4. `allUpper` = все буквы заглавные (≥2 букв): аббревиатура **или** Caps Lock в чужой раскладке. Не блокирует
   переключение, но блокирует исправление орфографии.
5. Считаем `altIsWord`: автопереключение включено, `altCore.Length ≥ minLen`, `altCore` словообразен (буквы, внутри
   допустимы `-` и апостроф), «буквы остаются буквами» (`alt.Length − altCore.Length ≤ typed.Length − core.Length`,
   иначе `ютуб` → `.ne,` считалось бы словом `ne`), и `IsKnown(altLang, altCore)`.
   - `minLen` = `MinWordLength` (по умолчанию 2), но для цели **английский** — минимум 3: английский словарь полон
     двухбуквенных аббревиатур (`nu`, `dr`), а `тг`/`вк` не должны превращаться в них.
6. **`IsKnown(lang, word)`** = в исключениях/белом списке, или `Hunspell.Check`, или «частотное разговорное»:
   ранг в частотном списке ≤ `KnownRankLimit` (RU 10 000, EN 5 000) для слов от 3 букв; двухбуквенные — только RU и
   ранг ≤ 5 000 (двухбуквенные токены в субтитрах — мусор: `lf` стоит на 2397 месте в английском списке).
   Благодаря этому `чо`, `щас`, `норм` — слова, и `xj` → `чо` переключается.
7. Если `core` словообразен и `IsKnown(typedLang, core)`:
   - если при этом `altIsWord` — **коллизия** (слово есть в обоих языках: `tot`/`еще`, `ye`/`ну`, `ult`/`где`,
     `pf`/`за`, `руку`/`here`, `рук`/`her`): `PreferOther` решает переключать или нет (§5). Иначе `Keep`.
8. Иначе если `altIsWord` → **`SwitchLayout`** (классический случай `ghbdtn` → `привет`).
9. Иначе если `allUpper` → `Keep`.
10. Иначе если автоисправление включено и (`core` — чистые буквы длиной `MinSpellFixLength`(3)…20, **или** `altCore`
    — чистые буквы длиной ≥ max(`MinSpellFixLength`, `minLen`) и ≤ 20 и буквы остаются буквами) →
    **`FixSpelling`** (само исправление считается асинхронно, §6.2).
11. Иначе `Keep`.

Что происходит по решению — §6.

## 5. Контекст языка и коллизии (`PreferOther`)

Для каждого окна (`hwnd`, словарь до 64 записей) хранится язык последних **настоящих** слов
(`IsRealWord`: словообразное, ≥2 букв, `IsKnown`). Обновляется при `Keep` настоящего слова, при любом переключении,
исправлении, ручном переключении и откате.

`PreferOther(core, typedLang, altCore, altLang, ctx)`:

- `ctx == altLang` → переключить («context»).
- `ctx == typedLang` → оставить.
- контекста нет → по частотности: переключить, только если `altRank ≤ 300` **и** (`typedRank` неизвестен, или
  `typedRank > 3000` и `typedRank ≥ 20 × altRank`). Так `tot`(23264) → `еще`(67), `ye`(3674) → `ну`(39), но
  `рук`(1624) / `her`(60) остаётся: первое слово в новом окне не должно ломаться из-за спорного случая.

Тот же `PreferOther` используется при ручном переключении раскладки посреди слова, если старое слово тоже валидно
(`ult` в EN + Alt+Shift: без контекста → `где`, с английским контекстом остаётся `ult`).

Контекст также даёт фору гипотезе при исправлении в двух раскладках (§6.2, `bias`).

## 6. Действия

### 6.1 SwitchLayout (синхронно, прямо в хуке)

Проверка поля пароля (§8) → если пароль, ничего не делаем. Иначе:
`SwitchLayoutVerified(hwnd, other)` (PostMessage `WM_INPUTLANGCHANGEREQUEST` окну с фокусом и верхнему окну),
`Injector.Replace(typed.Length, alt, boundaryVk)` — стереть слово, напечатать `alt`, нажать границу заново
(граница проглатывается: возвращаем `true` из хука). Контекст ← `altLang`. `Remember` для отката.

Почему синхронно: внутри колбэка аппаратной клавиши RIT (поток ввода Windows) заблокирован на нас — наш пакет гарантированно
попадёт в приложение до любой следующей клавиши пользователя. См. §7.

### 6.2 FixSpelling (асинхронно)

Пробел **не задерживается** (уходит в приложение сразу, набор не тормозит); Enter/Tab **задерживаются**
(`hold`), иначе в чате ушло бы неисправленное сообщение. Захватываем эпоху. В рабочем потоке:

`SpellFixer.FixEither(typed, layout, alt, other, allowSwitch, ctx)`:
- `asTyped = Fix(typed, layout)`, `asAlt = Fix(alt, other)` (параллельно).
- Гипотеза «другая раскладка + ошибка» должна быть убедительной: `asAlt.Score ≤ 1.3` и исправленное слово ≥ 4 букв
  (иначе `жызьн` уезжало в `;spy`). Если `asTyped` нет — берём `asAlt` с флагом `SwitchLayout`.
- Обе есть: `asTyped` побеждает, если `asTyped.Score ≤ asAlt.Score + bias`, где `bias` = −0.3 при контексте =
  язык `other`, +0.3 при контексте = язык набора, иначе +0.1.

`Fix(typed, hkl)`:
1. `core` < 3 букв или не чистые буквы → `Keep`.
2. Таблица автозамен (`dict/autocorrect.txt` + пользовательский, формат `что = на_что`) → мгновенный результат,
   score 0. Пример: `вобщем = в общем`, `alot = a lot`.
3. Набранное слово частотное (ранг ≤ `KnownRankLimit`) → `Keep` (разговорное, не трогать).
4. Иначе `ChooseBest` по нормализованному (нижний регистр, ё→е) слову → `MatchCase` под регистр оригинала
   (первая заглавная / весь КАПС), пунктуация с краёв возвращается.

`ChooseBest` — кандидаты (все должны быть в частотном списке **и** проходить `Hunspell.Check`; префильтр по
частотному списку — потому что он в 1000 раз быстрее):
1. **Пропущенный пробел** (только RU): все разбиения `a + " " + b`, обе части ранг ≤ 20 000 и валидны; цена 0.9,
   если обе части в топ-1000, иначе 1.25. (`инужно` → `и нужно`.) Английские составные слова слишком часто реальны
   (`raycast`), поэтому EN не разбиваем.
2. **Дешёвые замены** (`CheapVariants`): до 2 замен из таблиц типовых путаниц, лимит 400 вариантов.
   RU: а↔о, е↔и, и↔ы, е↔э, е↔я, о↔е, у↔ю, а↔я, з↔с, д↔т, б↔п, в↔ф, г↔к, ж↔ш, ч↔ш, щ↔ш, х↔г, ц↔с, ь↔ъ, й↔и.
   EN: a↔e, e↔i, a↔i, o↔u, s↔z, c↔s, c↔k, y↔i, a↔o, u↔i, g↔j, f↔v. (`малако` → `молоко`, `харашо` → `хорошо`.)
3. **Все одиночные правки** (`SingleEdits`): удаления, перестановки соседних, замены и вставки любой буквы алфавита.
4. **Двухшаговые** (слова ≥ 5 букв, бюджет 40 мс): первый шаг — правдоподобная оплошность (`LikelySlips`:
   перестановка 0.6, дешёвая замена 0.5, снятие удвоения 0.5), второй — любая одиночная правка. Цена кандидата =
   min(DP-расстояние, цена шага 1 + расстояние от промежуточного). Так берутся наложенные перестановки
   (`првеит` → `привет`), `здраствуйти`, `пирвте`, `definatley`. Пропуск буквы первым шагом не нужен — комбинация
   «пропуск + X» находится как «X + пропуск».
5. **Hunspell Suggest** (медленный, 30–100 мс) — только если лучший из быстрых кандидатов имеет score > 1.4.
   Даёт фонетические замены из REP-таблицы и n-gram-догадки.
Один и тот же кандидат из разных путей — берётся минимальная цена.

**Цена правки** (`EditCost.Distance`, DP по типу OSA):
- совпадение 0; дешёвая пара 0.5; соседняя клавиша (`TypoModel.AreNeighbours`, физическая сетка с учётом сдвига
  рядов) 0.7; прочая замена 1.0;
- перестановка соседних 0.6;
- **пропущенная** буква 0.75; 0.5, если она удваивает соседа, если это ь/ъ, или непроизносимая согласная рядом с
  согласной (`здраствуйте`, `сонце`, `лесница`);
- **лишняя** буква 1.0; 0.5, если удвоение или ь/ъ; 0.7, если согласная строго между двумя согласными
  (`интерестно`, но не `вторы` → `воры`); 1.2, если это последняя буква слова (`пивот` ≠ `пиво`).

**Score** = цена + штраф за редкость цели: `0.12·log10(rank)`, плюс `0.3·(log10(rank) − 4.3)` при rank > 20 000,
плюс `0.4·(log10(rank) − 4.7)` при rank > 50 000; цели вне списка не принимаются вовсе. Кандидаты сортируются по
score, берётся лучший.

**Принятие** лучшего кандидата:
- ранг известен;
- `score ≤ 1.5` для слов ≤ 5 букв, `≤ 1.7` для 6–7, `≤ 1.9` для ≥ 8 (длинное слово переживает две правки);
- 3 буквы: цена ≤ 0.6 и ранг ≤ 300 (EN) / 5 000 (RU) — иначе `sed → sad`, `awk → ask`;
- 4 буквы: цена ≤ 1.0 и ранг ≤ 10 000 — иначе `sudo → soda`, `vite → vita`;
- слово с заглавной буквы: ранг ≤ 10 000 — иначе `Вельск → Вольск`.

Применение результата — §7 (`ApplyFix`).

### 6.3 Ручное переключение раскладки посреди слова (`OnManualLayoutSwitch`)

Пользователь набрал `ult`, нажал Alt+Shift (или Win+Space) и продолжает. При следующей клавише раскладка окна ≠
раскладке буфера. Если `flipped` (буфер в новой раскладке) — известное слово ≥ 2 букв, а старое не известно (или
известно, но `PreferOther` за новое), и это не поле пароля → `Replace(typed.Length, flipped)` синхронно, буфер
переводится в новую раскладку (`SetLayout`), контекст ← новый язык. Текущая клавиша при этом проглатывается и
досылается сами: буква → `Push` + `PressKey`; граница → обычная обработка границы (+ `PressKey`, если она не была
проглочена); Backspace → снять + `PressKey`. Иначе → `Invalidate()`.

### 6.4 Горячая клавиша (Pause) и откат

Обрабатывается синхронно в колбэке (аппаратная клавиша → атомарная вставка).
- Буфер непуст (слово набирается) → перевести его в другую раскладку, переключить раскладку, `Remember`.
- Буфер пуст → взять `_last` (последнее законченное слово в этом окне, не старше 30 с; после Enter не запоминается —
  сообщение могло уйти): стереть `Text + trailing`, напечатать `AltText + trailing`, переключить раскладку.
  Если `_last.WasAuto` (это была автозамена) — это **откат**: исходное слово добавляется в `exceptions.txt`
  (в фоне) и больше никогда не трогается. Затем `_last` переворачивается — повторный Pause вернёт обратно.

## 7. Вставка текста — самая коварная часть

Эти факты установлены экспериментально, не меняй схему без перепроверки на `tools/e2e.ps1` со скан-кодовым typer'ом.

1. **`SendInput` внутри колбэка LL-хука аппаратной клавиши атомарен** относительно набора пользователя: RIT ждёт
   наш колбэк, ни одна аппаратная клавиша не может проскочить. Всё, что мы вставим, попадёт в приложение до текущей
   клавиши (если мы её проглотили и дошлём) и до всех последующих.
2. **Инжектированный ввод обрабатывается в контексте вставляющего потока**, а RIT в это время свободен и продолжает
   доставлять аппаратные клавиши. Поэтому вставка из колбэка *инжектированного* события (нашего триггера) или просто с
   рабочего потока при активном наборе **перемешивается** с клавишами пользователя.
3. **`SendInput` возвращается только после того, как LL-хуки обработали вставленные события.** Если вызвать его на
   потоке хука вне колбэка, или на другом потоке пока поток хука заблокирован ожиданием — это тупик до таймаута хука
   (~200–300 мс), и за это время клавиши пользователя тоже влезают. Поэтому:
   - все `SendInput` делает отдельный поток-инжектор (`Injector._thread`);
   - если вызов идёт из колбэка (`KeyboardHook.InCallback`), поток хука **ждёт завершения, прокачивая свои же
     колбэки** (`PeekMessage(PM_QS_SENDMESSAGE)` + `MsgWaitForMultipleObjectsEx`), с потолком 250 мс;
   - иначе — «выстрелил и забыл».
4. На машине автора любое инжектированное событие стоит ~5 мс (длинная цепочка чужих LL-хуков: `CallNextHookEx`
   дорогой), т.е. замена слова из 7 букв ≈ 30 событий ≈ 150 мс заморозки ввода. Экономить события **нельзя** через
   автоповтор Backspace (N нажатий + одно отпускание) и одиночные key-up для Unicode: Chromium/Electron (Claude,
   Telegram, браузеры, Discord) такие повторы игнорируют, стирание не происходит, слово дописывается к старому
   (`наренапример`) — так сломалась версия 0.1.0. Каждое событие — пара down/up.
5. Отсюда схема **отложенного исправления** (`RunInHook` / `ApplyFix`): рабочий поток посчитал исправление →
   если последняя аппаратная клавиша была < 150 мс назад (пользователь печатает) — ждём **следующую аппаратную
   клавишу** и применяем исправление в её колбэке, до неё (буквы уже начатого следующего слова стираются и
   перепечатываются вместе с исправленным словом, в новой раскладке, если переключились); если клавиши нет 150 мс —
   применяем через **триггер** (`SendTrigger`: инжектированное нажатие неиспользуемого VK 0xE8 с сигнатурой `LFTR`;
   хук глотает его и выполняет очередь `_deferred`). В паузе перемешиваться не с чем.
6. `ApplyFix` перед вставкой проверяет: эпоха не изменилась, буфер принадлежит тому же окну. Иначе исправление
   **пропускается** (если Enter/Tab был задержан — просто досылается). Лучше одна непоправленная опечатка, чем каша.
   Число Backspace = `typed.Length + (граница уже ушла ? 1 : 0) + длина уже набранных букв следующего слова`.
7. `SwitchLayoutVerified`: опциональный (`ToggleHotkeyIfIgnored`, по умолчанию **выкл.**) страховочный Alt+Shift /
   Ctrl+Shift / Win+Space через 400 мс, если приложение так и осталось в старом *языке* (сравнивать надо
   `LangId`, не HKL — один и тот же язык может вернуться другим дескриптором). Выключен, потому что приложение,
   обрабатывающее запрос с задержкой, оказалось бы перевёрнутым дважды.

## 8. Поля паролей (`PasswordDetector`)

Замаскированный пароль в чужой раскладке превратился бы в кириллицу, и пользователь не понял бы, почему не пускает.
- Мгновенно: класс окна с фокусом содержит `EDIT` и стиль `ES_PASSWORD` (Win32, WinForms).
- В фоне (STA-поток, TTL 1 с, обновление при каждой клавише/клике, если устарело): UI Automation.
  **Нельзя использовать `AutomationElement.FocusedElement`** — он делает `AttachThreadInput` к потоку окна, а Windows
  при этом **синхронизирует раскладку** между потоками, и раскладка приложения подменяется на нашу. Используются
  `FromPoint(позиция каретки из GetGUIThreadInfo)` и `FromHandle(окно с фокусом)` → `Current.IsPassword`.
- Решение всегда берёт последний известный ответ, никогда не ждёт. `SWITCHER_NO_UIA=1` отключает UIA.
- Проверяется перед переключением, перед исправлением и при ручном перевороте; горячая клавиша — нет (явное
  действие пользователя).

## 9. Настройки (`settings.json`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `SettingsVersion` | 2 | Версия схемы; при повышении дефолтов старый файл мигрируется (`Load`). |
| `Enabled` | true | Главный выключатель (двойной клик по иконке). |
| `AutoSwitchLayout` | true | Автопереключение раскладки. |
| `AutoFixSpelling` | true | Автоисправление. |
| `MinWordLength` | 2 | Минимум букв для переключения (к EN всё равно ≥ 3). |
| `MinSpellFixLength` | 3 | Минимум букв для исправления. |
| `ToggleHotkeyIfIgnored` | false | См. §7 п.7. |
| `Beep` | false | Звук при замене. |
| `LogActions` | true | Писать замены в `log.txt`. |
| `Hotkey` | "Pause" | `Ctrl+Shift+Key`, имена из `System.Windows.Forms.Keys`. Читается при старте. |
| `ExcludedProcesses` | список выше | Имена процессов без `.exe`. |

Переключатели в меню трея применяются сразу; правки файлов руками — после «Перезапустить».

`exceptions.txt` (пользовательский) и `dict/whitelist.txt` (встроенный) — одно множество «известных слов»: они не
трогаются **и** считаются валидными целями переключения (`yjhv` → `норм`). Белый список содержит тех-слова
(`json`, `async`, `sudo`, `vite`…), интернет-сленг (`лол`, `кек`, `норм`), геймдев-жаргон со склонениями (`меш/мешей`,
`пивот/пивоты`, `ассеты`, `рейкаст`, `юнька`…). Пополнять при ложных срабатываниях **классами**, а не по одному слову,
если видна закономерность.

## 11. Тестирование

- **`Switcher.exe --test слово…`** / `--test @файл` — решение по каждому слову без клавиатуры. Язык набора
  определяется по первой букве (кириллица → набирали в RU). Префикс `ru:`/`en:` задаёт контекст. Вывод:
  `SWITCH → …`, `FIX → …`, `FIX+SW → …`, `keep`, время. Наборы, которыми тюнились правила, лежат в `tools/testsets/`:
  `ortho.txt` — 58 орфографических ошибок, `two-errors.txt` — 43 слова с двумя ошибками, `jargon-keep.txt` — 80 редких,
  но правильных жаргонных слов (ни одного FIX!), `tech-keep.txt` — тех-слова, `slang-and-short.txt` — сленг и короткие
  слова, `context.txt` — коллизии с префиксами `ru:`/`en:`. При правках
  метрики прогоняй такие же наборы: **ни одного FIX на жаргоне, все типовые ошибки исправлены**.
- **`tools\e2e.ps1`** (39 кейсов) — поднимает форму с TextBox, запускает Switcher с тестовой папкой данных
  (`%TEMP%\Switcher_e2e`, hotkey F9), печатает и сверяет. Печать — двумя способами: `SendKeys` (старые кейсы) и
  `tools\typer.py` (скан-коды, паузы между клавишами, реальный Alt+Shift). Параметры `-Only <подстрока>`, `-Debug`,
  `-NoUia`. Защита: не печатает, если окно теста не на переднем плане (и typer проверяет это сам).
  **Правило пользователя: запускать только с его разрешения** — тест захватывает экран. При работающем пользователе
  флейкает по фокусу. Известные артефакты стенда: `SendKeys` после смены раскладки шлёт латиницу Unicode-пакетами
  (поэтому после переключения текст задаётся кириллицей), а его journal-hook присоединяет очереди ввода.

## 12. Сборка и релиз

- `install.ps1` — `dotnet publish` self-contained single-file win-x64 (чистит `publish/`, иначе инкрементальный
  publish не докладывает файлы), `robocopy /MIR` в `%LocalAppData%\Programs\Switcher` (не `Copy-Item *` — теряет
  вложенные файлы в PS 5.1), автозапуск, запуск. Убирает старую установку LayoutFix.
- PowerShell-скрипты с кириллицей — **UTF-8 с BOM и CRLF**, иначе PS 5.1 ломается на «умных кавычках».
- Релиз: поднять `<Version>` в `Switcher.csproj`, закоммитить, тег `vX.Y.Z`, `Compress-Archive publish\* →
  Switcher-win-x64.zip` (в `.gitignore`!), создать релиз и загрузить ассет через GitHub API. Токен — из Git
  Credential Manager (`git credential fill`), `gh` не установлен и не нужен. JSON для API писать в файл с
  `ensure_ascii` — кириллица в `-d` ломала парсер.

## 13. Известные ограничения и идеи

- Границы слова — только пробел/Enter/Tab; знаки препинания уходят вместе со словом.
- Не работает в окнах с правами администратора (UIPI) и в играх с анти-читом.
- После Enter откат невозможен.
- Слова длиннее 20 букв не исправляются; > 64 клавиш буфер сбрасывается.
- Идеи: переключение выделенного текста (Shift+Pause через буфер обмена); вставка через буфер обмена вместо
  посимвольного Unicode (2 события вместо 2×N — но клобберит clipboard); обёртка для e2e «когда пользователь
  отошёл» (`GetLastInputInfo`); GUI настроек; подпись exe (SmartScreen).
